# Navigation Policy Model — System Interface

This document describes every input and output of the navigation policy model at inference time, and how each signal maps to hardware/ROS sources on the competition robot.

---

## Nav Model Inputs (per 10 Hz inference step)

| Input | Shape | Dtype | Source |
|-------|-------|-------|--------|
| `terrain` | `(5, 60, 60)` | float32 | Terrain mapper (ch 0–3) + zone script (ch 4) |
| `heading` | `(2,)` | float32 | IMU / odometry → `[sin(yaw), cos(yaw)]` |
| `zone_idx` | scalar | long (0–5) | Zone script (arena YAML + robot position) |
| `arena_type` | scalar | float (0.0 / 1.0) | Hardcoded at deployment — UCF=0.0, KSC=1.0 |
| `phase_idx` | scalar | long (0–3) | Mission state machine |
| `hidden` | `(h_n, c_n)` | tensors | LSTM state — carried forward from previous step, `None` at start of run |

---

## Nav Model Outputs

| Output | Shape | Meaning |
|--------|-------|---------|
| `left_motor` | scalar | tanh ∈ [−1, 1] — multiply by `nav_speed_limit` (0.20 m/s) to get motor command |
| `right_motor` | scalar | same |
| `bucket` | scalar int | 0 = UP (travel) · 1 = COLLECT (digging) · 2 = DUMP |
| `new_hidden` | `(h_n, c_n)` | Save and pass back as `hidden` on the next step; reset to `None` at the start of each arena run |

---

## Terrain Mapper → Nav Model Channel Mapping

The terrain mapper (`ros_intro` branch, `/octane_terrain_mapping`) outputs three ROS streams. Channels 0–3 of the terrain input come directly from those streams; channel 4 is generated by the zone script.

| Nav terrain channel | Terrain mapper source | Conversion |
|---------------------|-----------------------|------------|
| Ch 0 — height | `/terrain/heightmap` (200×200 float32, 0.05 m/cell) | Crop 4 m × 4 m patch centred on robot |
| Ch 1 — rocks | `/terrain/semantic` class label == 1 | Binary mask → float32, same crop |
| Ch 2 — craters | `/terrain/semantic` class label == 2 | Binary mask → float32, same crop |
| Ch 3 — walls | `/terrain/semantic` class label == 3 | Binary mask → float32, same crop |
| Ch 4 — goal heatmap | **Not from terrain mapper** | Computed by zone script (see below) |

### Resolution note

The terrain mapper runs at **0.05 m/cell** (200×200 grid, 10 m × 10 m coverage).  
Training used **0.1 m/cell** synthetic maps.

`crop_robot_view` in `training_nav/arena.py` handles resampling — it always outputs a 60×60 crop covering exactly 4 m × 4 m regardless of source resolution. When calling it with the live map, pass `cell_size=0.05` in the config to match the terrain mapper's grid spacing.

## Zone Script (your team builds this)

```
Inputs:
  arena.yaml          — zone boundary definitions (x, y, w, h per zone)
  robot position      — (x, y) from ROS odometry / SLAM

Outputs:
  zone_idx   int      — current zone (see table below)
  goal_hmap  float32  — (60, 60) goal heatmap for terrain channel 4
```

### Zone index table

| `zone_idx` | Zone name |
|-----------|-----------|
| 0 | `start` |
| 1 | `excavation` |
| 2 | `nav` |
| 3 | `deposit` |
| 4 | `berm_target` |
| 5 | `outside` (default if none match) |

The helper functions already exist in `training_nav/arena.py`:

```python
from training_nav.arena import current_zone, build_goal_heatmap

zone_name = current_zone(arena, robot_x, robot_y)   # returns string key
zone_idx  = _ZONE_IDX[zone_name]                    # integer 0-5

goal_hmap = build_goal_heatmap(arena, goal_zone, robot_x, robot_y, cfg)
# returns (60, 60) float32 — feed as terrain channel 4
```

## Phase index table

The mission state machine (separate ROS node) maintains the current phase and publishes it as an integer.

| `phase_idx` | Phase | Bucket state | Behaviour |
|------------|-------|-------------|-----------|
| 0 | `to_excavation` | UP | Navigate from start/nav zone to excavation zone |
| 1 | `digging` | COLLECT | Slow forward movement in excavation zone |
| 2 | `to_deposit` | UP | Navigate from excavation zone to berm target |
| 3 | `dumping` | DUMP | Stopped at berm — deposit payload |

## LSTM State Management

```python
hidden = None          # at the start of each arena run

# per-step (10 Hz):
out, hidden = model(terrain, heading, zone_idx, arena_type, phase_idx, hidden)
left, right, bucket = NavPolicy.decode(out)
# hidden is saved and passed back next step automatically
```

Reset `hidden = None` when:
- Starting a new run / arena
- After a collision / recovery reset
- Whenever the mission controller declares a full restart

---

## What the model does NOT receive

- Raw (x, y) position coordinates
- Arena dimensions or scale
- Global terrain map (only the 4 m × 4 m local sensor crop)
- Phase transition triggers (the state machine decides when to advance phase, not the model)
