# Navigation Policy Model — System Interface

This document describes every input, output, and internal structure of the OCTANE navigation policy
at inference time, and how each signal maps to hardware/ROS sources on the competition robot.

---

## Nav Model Inputs (per 10 Hz inference step)

| Input | Shape | Dtype | Source |
|-------|-------|-------|--------|
| `terrain` | `(1, 5, 80, 80)` | float32 | Terrain model (ch 0–3) + mission planner (ch 4) |
| `heading` | `(1, 2)` | float32 | IMU / odometry → `[sin(yaw), cos(yaw)]` |
| `zone_idx` | `(1,)` | long (0–5) | Zone script (arena YAML + robot position) |
| `arena_type` | `(1,)` | float (0.0 / 1.0) | Hardcoded at deployment — UCF=0.0, KSC=1.0 |
| `phase_idx` | `(1,)` | long (0–3) | Mission state machine |
| `hidden` | `(h_n, c_n)` | tensors | LSTM state — carried forward each step, `None` at run start |

> All batch-T dims collapse to `(1, 1, …)` for single-step inference; the model processes sequence
> dimension T=1 per call at runtime.

---

## Nav Model Outputs

| Output | Shape | Meaning |
|--------|-------|---------|
| `left_motor` | scalar | tanh ∈ [−1, 1] — scale by `nav_speed_limit` (0.20) to get motor command |
| `right_motor` | scalar | same |
| `bucket_logits` | `(3,)` | argmax → 0 = UP (travel) · 1 = COLLECT (digging) · 2 = DUMP |
| `new_hidden` | `(h_n, c_n)` | Pass back as `hidden` next step; reset to `None` at run start |

## Terrain Model → Nav Model Integration Contract

The terrain model (`ml/terrain_model` branch) and nav model share **identical resolution**
(0.05 m/cell). The only transform needed at deployment is a **center crop** — no resampling.

### Terrain model output

| Property | Value |
|----------|-------|
| Output keys | `height`, `rocks`, `craters`, `walls` |
| Tensor shape | `(B, 200, 200)` float32 each |
| Resolution | 0.05 m/cell |
| Coverage | 10 m × 10 m centred on robot |
| Robot pixel | `(100, 100)` — centre of the 200×200 grid |

### Deployment crop

The nav model needs ±2 m (80 cells × 0.05 m). Crop from the terrain model:

```
rows [60:140], cols [60:140]  →  exact 80×80, no resize
```

```
terrain 200×200
┌──────────────────────────┐
│        5 m margin        │
│   ┌──────────────┐  r=60 │
│   │  nav crop    │       │
│   │  80×80       │       │
│   │  (±2 m)      │       │
│   └──────────────┘ r=140 │
│                          │
└──────────────────────────┘
0    c=60      c=140     200
```

```python
# training_nav/integration.py — terrain_to_nav_input()
_CROP_SLICE = slice(60, 140)

height  = terrain_out['height'] [..., _CROP_SLICE, _CROP_SLICE]  # (B, 80, 80)
rocks   = terrain_out['rocks']  [..., _CROP_SLICE, _CROP_SLICE]
craters = terrain_out['craters'][..., _CROP_SLICE, _CROP_SLICE]
walls   = terrain_out['walls']  [..., _CROP_SLICE, _CROP_SLICE]
goal    = goal_heatmap                                            # (B, 80, 80) — from mission planner

nav_input = torch.stack([height, rocks, craters, walls, goal], dim=-3)  # (B, 5, 80, 80)
```

See `training_nav/integration.py` for the full adapter and `make_goal_heatmap()`.

### Channel mapping

| Nav channel | Terrain model key | Notes |
|-------------|------------------|-------|
| Ch 0 — height | `height` | Continuous float32 elevation |
| Ch 1 — rocks | `rocks` | Binary mask (0 or 1) |
| Ch 2 — craters | `craters` | Binary mask (0 or 1) |
| Ch 3 — walls | `walls` | Binary mask — 1.0 at arena walls, 0.0outside arena |
| Ch 4 — goal heatmap | **Not from terrain model** | Gaussian centred on goal zone, generated by mission planner |

> Out-of-arena regions are filled with **0.0** on all channels (no signal, not a synthetic wall).

## Zone Script (your team builds this)

```
Inputs:
  arena.yaml          — zone boundary definitions (x, y, w, h per zone)
  robot position      — (x, y) from ROS odometry / SLAM

Outputs:
  zone_idx   int      — current zone (see table below)
  goal_hmap  float32  — (80, 80) goal heatmap for terrain channel 4
```

### Zone index table

| `zone_idx` | Zone name |
|-----------|-----------|
| 0 | `start` |
| 1 | `excavation` |
| 2 | `nav` |
| 3 | `deposit` |
| 4 | `berm_target` |
| 5 | `outside` (default if none match) |

## Phase Index Table

| `phase_idx` | Phase | Bucket state | Behaviour |
|------------|-------|-------------|-----------|
| 0 | `to_excavation` | UP | Navigate from start/nav zone to excavation zone |
| 1 | `digging` | COLLECT | Slow forward movement in excavation zone |
| 2 | `to_deposit` | UP | Navigate from excavation to berm target |
| 3 | `dumping` | DUMP | Stopped at berm — deposit payload |

## Model Architecture

```
Input: (B, T, 5, 80, 80)
         │
         ▼
┌─────────────────────────────────────────────────────┐
│  CNN  (4 convolutional blocks, ~4.7 M params)       │
│  channels: [64, 128, 256, 512]                      │
│  each block: Conv2d → BatchNorm → ReLU → MaxPool    │
│                 ↓                                   │
│  AdaptiveAvgPool2d(1)  →  (B·T, 512)               │
└─────────────────────────────────────────────────────┘
         │
         ├── heading_mlp  : (2,)   → Linear(2→16)  → ReLU   (16-d)
         ├── zone_emb     : long   → Embedding(6, 8)         ( 8-d)
         ├── arena_mlp    : float  → Linear(1→8)   → ReLU   ( 8-d)
         └── phase_emb    : long   → Embedding(4, 8)         ( 8-d)
         │
         ▼  concat → (B·T, 512+16+8+8+8) = (B·T, 552)
┌─────────────────────────────────────────────────────┐
│  fc_in: Linear(552 → 512) → LayerNorm → ReLU       │
└─────────────────────────────────────────────────────┘
         │ reshape → (B, T, 512)
         ▼
┌─────────────────────────────────────────────────────┐
│  LSTM  (2 layers, hidden=512, ~4.2 M params)        │
│  Input: (B, T, 512)  →  Output: (B, T, 512)        │
└─────────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────┐
│  MLP head: Linear(512→256) → ReLU → Linear(256→128)│
│            → ReLU → Linear(128→5)                  │
└─────────────────────────────────────────────────────┘
         │
         ├── motor_head  : out[:2] → tanh     →  (left, right)
         └── bucket_head : out[2:] → (logits) →  argmax → {0, 1, 2}

Total parameters: ~9 M
```

> `AdaptiveAvgPool2d(1)` makes the CNN spatially resolution-agnostic. The model accepts any
> grid size at training or deployment — changing `grid_size` in config does not require
> retraining the CNN layers.

## Loss Function

Training uses behavioural cloning (imitation learning) with five combined losses:

```
total = Huber(motors)
      + w_bucket  × CrossEntropy(bucket)
      + w_speed   × speed_floor_penalty
      + w_prox    × proximity_penalty
      + w_idle    × idle_penalty
```

| Component | Weight (config) | Description |
|-----------|----------------|-------------|
| **Huber (motors)** | δ=0.1 | L1/L2 blend on left/right motor commands vs expert |
| **CrossEntropy (bucket)** | `bucket_loss_weight = 0.50` | Bucket state classification (0/1/2) |
| **Speed floor** | `speed_reg_weight = 0.01` | Penalises predicted speed < 0.30 when expert is moving (>0.15); prevents mode collapse toward zero |
| **Proximity** | `proximity_reg_weight = 0.03` | Penalises speed proportional to max obstacle presence in view (rocks ch1 + craters ch2, clamped to [0,1], then element-wise max with walls ch3) |
| **Idle** | `idle_reg_weight = 0.003` | Tiny constant pressure against near-zero predictions on all steps; prevents silent zero-output |

> Logged losses are multiplied by `loss_display_scale = 100` for readability only — this has no
> effect on gradients.

## Curriculum Stages

| Stage | Epoch range | `seq_len` | Duration (s) | Description |
|-------|------------|-----------|-------------|-------------|
| 0 — goal-seeking | 1 – 39 | 8 | 0.8 s | Empty arena, no obstacles; robot learns to track goal heatmap |
| 1 — basic avoidance | 40 – 89 | 48 | 4.8 s | 1–2 obstacles; robot travels ~0.96 m, enough to encounter and avoid |
| 2 — full obstacles + DART | 90 – 149 | 128 | 12.8 s | Full obstacle density + 30% DART recovery perturbations (σ=0.18 m) |
| 3 — hardening | 150+ | 256 | 25.6 s | Same as stage 2 + heavier DART (50%, σ=0.32 m); runs until early stop |

Early stopping fires only after stage 2 is complete (epoch ≥ 150), with patience = max(60, epochs/50).

## LSTM State Management

```python
hidden = None          # reset at the start of each arena run

# per-step (10 Hz):
out, hidden = model(terrain, heading, zone_idx, arena_type, phase_idx, hidden)
left  = out[0, 0, 0].item()    # motor
right = out[0, 0, 1].item()    # motor
bucket_class = out[0, 0, 2:].argmax().item()
# hidden is automatically carried forward
```

Reset `hidden = None` when:
- Starting a new run / arena
- After a collision / recovery reset
- Whenever the mission controller declares a full restart

---

## What the Model Does NOT Receive

- Raw (x, y) position coordinates
- Arena dimensions or scale
- Global terrain map (only the 4 m × 4 m local sensor crop)
- Phase transition triggers (the state machine decides when to advance phase, not the model)
